# MyBlog 错误码文档

本文档以 `ErrorCode.java` 和 `GlobalExceptionHandler.java` 的当前实现为准。

## 1. 响应规则

- `code = 0` 表示成功，其余均为失败。
- 客户端使用 `code` 做业务判断，HTTP 状态用于协议层处理。
- `message` 是稳定中文说明；具体原因优先读取 `error`。
- 服务端异常不会向客户端返回 SQL、堆栈或内部异常消息。

编码范围：

| 范围 | 业务域 |
| --- | --- |
| `0` | 成功 |
| `10001～10999` | 通用请求、安全和 HTTP 协议 |
| `11001～11999` | 管理员账号与登录 |
| `12001～12999` | 内容管理与发布 |
| `13001～13999` | 文件与对象存储 |
| `20001～20999` | 服务端与数据库 |

## 2. 完整错误码

### 2.1 通用请求与安全

| code | HTTP | 标识 | 默认说明 | 当前常见场景 |
| ---: | ---: | --- | --- | --- |
| 10001 | 401 | `AUTHENTICATION_FAILED` | 身份认证失败 | 缺少、损坏、类型错误的访问令牌；当前用户不存在 |
| 10002 | 401 | `TOKEN_EXPIRED` | 登录凭证已过期 | access token 或 refresh token 过期 |
| 10003 | 401 | `TOKEN_REVOKED` | 登录凭证已失效 | 令牌已被 `/auth/logout-token` 吊销 |
| 10004 | 403 | `FORBIDDEN` | 无权执行该操作 | 角色低于接口要求 |
| 10005 | 404 | `RESOURCE_NOT_FOUND` | 请求的资源不存在 | MyLab 卡片、标签或路由不存在 |
| 10006 | 409 | `RESOURCE_CONFLICT` | 资源状态冲突 | 唯一键冲突、标签重复、文件仍被内容引用 |
| 10007 | 422 | `VALIDATION_FAILED` | 请求参数校验失败 | Bean Validation、用户字段或必填 token 校验失败 |
| 10008 | 429 | `RATE_LIMIT_EXCEEDED` | 请求过于频繁 | 超过全局或登录接口每分钟限额 |
| 10009 | 400 | `MALFORMED_REQUEST` | 请求体格式错误 | JSON 语法或字段类型错误 |
| 10010 | 405 | `METHOD_NOT_ALLOWED` | 请求方法不支持 | 请求路径存在但 HTTP 方法错误 |
| 10011 | 415 | `UNSUPPORTED_MEDIA_TYPE` | 请求媒体类型不支持 | 请求 `Content-Type` 不受支持 |
| 10012 | 400 | `MISSING_REQUEST_PARAMETER` | 缺少必填请求参数 | 缺少 query 参数或 multipart 的 `file` part |
| 10013 | 400 | `PARAMETER_TYPE_MISMATCH` | 请求参数类型错误 | UUID、整数等路径或查询参数格式错误 |

### 2.2 管理员账号与登录

| code | HTTP | 标识 | 默认说明 | 当前常见场景 |
| ---: | ---: | --- | --- | --- |
| 11001 | 401 | `INVALID_CREDENTIALS` | 用户名或密码错误 | 登录失败；不区分用户名和密码错误 |
| 11002 | 401 | `ACCOUNT_DISABLED` | 账号已被停用 | 刷新令牌时用户不存在或已停用 |
| 11003 | 422 | `OLD_PASSWORD_INCORRECT` | 原密码错误 | 修改当前用户密码失败 |
| 11004 | 404 | `USER_NOT_FOUND` | 用户不存在 | 更新或删除目标用户不存在 |
| 11005 | 409 | `USER_ALREADY_EXISTS` | 用户名或邮箱已存在 | 创建用户时用户名重复；当前用户表不包含邮箱字段 |

### 2.3 内容管理

| code | HTTP | 标识 | 默认说明 | 当前常见场景 |
| ---: | ---: | --- | --- | --- |
| 12001 | 404 | `CONTENT_MODULE_NOT_FOUND` | 内容模块不存在 | `moduleKey` 不在五个合法模块中 |
| 12002 | 404 | `CONTENT_MODULE_OFFLINE` | 内容模块已下线 | 公开读取没有 `PUBLISHED` 版本的模块 |
| 12003 | 404 | `CONTENT_VERSION_NOT_FOUND` | 内容版本不存在 | 指定版本或当前草稿不存在 |
| 12004 | 422 | `CONTENT_VALIDATION_FAILED` | 内容数据校验失败 | 内容结构、字段组合、标签、排序、百分比或资源 MIME 不合法 |
| 12005 | 409 | `CONTENT_DEPENDENCY_CONFLICT` | 内容关联关系冲突 | 草稿乐观锁冲突、缺少草稿、重复发布/下线、恢复前已有草稿 |

### 2.4 文件与对象存储

| code | HTTP | 标识 | 默认说明 | 当前常见场景 |
| ---: | ---: | --- | --- | --- |
| 13001 | 422 | `FILE_EMPTY` | 上传文件为空 | 上传文件大小为 0 |
| 13002 | 415 | `FILE_TYPE_UNSUPPORTED` | 文件类型不支持 | MIME 不在图片、PDF、Markdown、纯文本白名单中 |
| 13003 | 413 | `FILE_TOO_LARGE` | 上传文件超过大小限制 | 超过 Spring multipart 或 `OSS_MAX_FILE_SIZE_MB` 限制 |
| 13004 | 404 | `FILE_NOT_FOUND` | 文件不存在 | 获取地址或删除的资源不存在/已删除 |
| 13005 | 503 | `STORAGE_UNAVAILABLE` | 文件存储服务不可用 | OSS 未配置、上传失败、签名或删除操作失败 |

### 2.5 服务端错误

| code | HTTP | 标识 | 默认说明 | 当前常见场景 |
| ---: | ---: | --- | --- | --- |
| 20001 | 500 | `INTERNAL_ERROR` | 服务器内部错误 | 未归类异常 |
| 20002 | 500 | `DATABASE_ERROR` | 数据库操作失败 | 数据源、SQL 或事务异常；唯一键冲突优先映射为 `10006` |

## 3. 全局异常映射

| 异常类型 | 错误码 |
| --- | --- |
| 业务 `BaseException` | 使用异常携带的错误码 |
| `MethodArgumentNotValidException`、`ConstraintViolationException` | `10007` |
| `HttpMessageNotReadableException` | `10009` |
| 缺少 query 参数或 multipart part | `10012` |
| 路径、query 参数类型错误 | `10013` |
| HTTP 方法不支持 | `10010` |
| HTTP 媒体类型不支持 | `10011` |
| Spring 上传总大小超限 | `13003` |
| 路由不存在 | `10005` |
| `DuplicateKeyException` | `10006` |
| 其他 `DataAccessException` | `20002` |
| 其他异常 | `20001` |

## 4. 后台客户端处理

| 错误码 | 建议行为 |
| --- | --- |
| `10001～10003`、`11002` | 尝试刷新令牌；刷新失败后清理会话并跳转登录页 |
| `11001` | 停留在登录页并显示登录失败 |
| `10004` | 显示无权限提示，不重试 |
| `10005`、`11004`、`12001～12003`、`13004` | 提示资源不存在并刷新当前数据 |
| `10006`、`11005`、`12005` | 保留用户输入，展示冲突详情并要求刷新或调整数据 |
| `10007`、`10009`、`10012～10013`、`12004` | 优先展示 `error`，引导用户修正表单 |
| `10008` | 等待后重试，不立即并发重放 |
| `13001～13003` | 重新选择符合 MIME 和大小限制的文件 |
| `13005`、`20001～20002` | 提示稍后重试；需要排查时可记录响应头 `X-Request-ID` |

## 5. 维护约定

新增或调整错误码时，需要同时完成：

1. 修改 `ErrorCode.java`，确保编号全局唯一。
2. 通过业务异常或全局异常处理器建立明确映射。
3. 更新本文档中的默认说明、HTTP 状态和实际触发场景。
4. 为错误码唯一性和异常映射补充测试。
5. 检查 `/v3/api-docs` 和 `/swagger-ui.html` 的响应模型。
