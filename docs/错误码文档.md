# MyBlog 错误码文档

## 1. 编码规范

错误码是稳定的五位数字。已有 `10001～10008` 和 `20001` 保持兼容，新增错误按业务域划分：

| 范围 | 业务域 |
| --- | --- |
| `0` | 成功 |
| `10001～10999` | 通用请求、安全、鉴权和 HTTP 协议错误 |
| `11001～11999` | 管理员账号与登录错误 |
| `12001～12999` | 内容管理、发布和关联关系错误 |
| `13001～13999` | 文件上传和对象存储错误 |
| `20001～20999` | 服务端、数据库和不可恢复错误 |

约束：

1. 每个错误码全局唯一，不得复用为不同语义。
2. `message` 是稳定中文说明，客户端不得依赖完整句子做逻辑判断。
3. 客户端逻辑判断使用 `code`，HTTP 状态用于协议层处理。
4. `error` 仅提供可安全展示的校验细节，可能为空。
5. 未知服务端异常不得把异常类名、SQL、堆栈或内部异常消息返回给客户端。
6. 每次错误响应必须包含 `request_id` 和 `timestamp`。

代码中的权威定义位于 `backend-java/src/main/java/com/myblog/common/enumeration/ErrorCode.java`。

## 2. 完整错误码表

### 2.1 成功

| 错误码 | HTTP | 标识 | 默认说明 |
| --- | ---: | --- | --- |
| 0 | 200 | `SUCCESS` | 成功 |

### 2.2 通用请求与安全错误

| 错误码 | HTTP | 标识 | 默认说明 | 常见场景 |
| --- | ---: | --- | --- | --- |
| 10001 | 401 | `AUTHENTICATION_FAILED` | 身份认证失败 | 缺少、损坏或类型不正确的访问令牌 |
| 10002 | 401 | `TOKEN_EXPIRED` | 登录凭证已过期 | access_token 或 refresh_token 已过期 |
| 10003 | 401 | `TOKEN_REVOKED` | 登录凭证已失效 | 令牌已加入吊销列表 |
| 10004 | 403 | `FORBIDDEN` | 无权执行该操作 | 非管理员或非 superadmin 执行受限操作 |
| 10005 | 404 | `RESOURCE_NOT_FOUND` | 请求的资源不存在 | 普通资源或路由不存在 |
| 10006 | 409 | `RESOURCE_CONFLICT` | 资源状态冲突 | 唯一键冲突或资源当前状态不允许操作 |
| 10007 | 422 | `VALIDATION_FAILED` | 请求参数校验失败 | Bean Validation 或通用业务参数校验失败 |
| 10008 | 429 | `RATE_LIMIT_EXCEEDED` | 请求过于频繁 | 超过全局或登录接口每分钟限制 |
| 10009 | 400 | `MALFORMED_REQUEST` | 请求体格式错误 | JSON 语法错误或 JSON 字段类型错误 |
| 10010 | 405 | `METHOD_NOT_ALLOWED` | 请求方法不支持 | 用 POST 调用仅支持 GET 的路径 |
| 10011 | 415 | `UNSUPPORTED_MEDIA_TYPE` | 请求媒体类型不支持 | Content-Type 不被接口接受 |
| 10012 | 400 | `MISSING_REQUEST_PARAMETER` | 缺少必填请求参数 | 缺少 query 参数或 multipart part |
| 10013 | 400 | `PARAMETER_TYPE_MISMATCH` | 请求参数类型错误 | UUID、日期、整数等路径或查询参数格式错误 |

### 2.3 管理员账号错误

| 错误码 | HTTP | 标识 | 默认说明 | 常见场景 |
| --- | ---: | --- | --- | --- |
| 11001 | 401 | `INVALID_CREDENTIALS` | 用户名或密码错误 | 登录凭证不正确；不区分用户名和密码以避免账号探测 |
| 11002 | 401 | `ACCOUNT_DISABLED` | 账号已被停用 | 刷新令牌时账号已经停用 |
| 11003 | 422 | `OLD_PASSWORD_INCORRECT` | 原密码错误 | 修改密码时原密码不匹配 |
| 11004 | 404 | `USER_NOT_FOUND` | 用户不存在 | 更新或删除的管理员账号不存在 |
| 11005 | 409 | `USER_ALREADY_EXISTS` | 用户名或邮箱已存在 | 创建管理员时唯一键冲突 |

### 2.4 内容管理错误

| 错误码 | HTTP | 标识 | 默认说明 | 常见场景 |
| --- | ---: | --- | --- | --- |
| 12001 | 404 | `CONTENT_MODULE_NOT_FOUND` | 内容模块不存在 | moduleKey 不在允许列表或模块未初始化 |
| 12002 | 404 | `CONTENT_MODULE_OFFLINE` | 内容模块已下线 | 公开接口读取已下线模块 |
| 12003 | 404 | `CONTENT_VERSION_NOT_FOUND` | 内容版本不存在 | 回滚目标版本不存在 |
| 12004 | 422 | `CONTENT_VALIDATION_FAILED` | 内容数据校验失败 | 百分比、必填字段、唯一性或时间格式不符合规则 |
| 12005 | 409 | `CONTENT_DEPENDENCY_CONFLICT` | 内容关联关系冲突 | 项目引用未发布 myLab，或删除被线上项目引用的 myLab 记录 |

### 2.5 文件与存储错误

| 错误码 | HTTP | 标识 | 默认说明 | 常见场景 |
| --- | ---: | --- | --- | --- |
| 13001 | 422 | `FILE_EMPTY` | 上传文件为空 | multipart 文件大小为 0 |
| 13002 | 415 | `FILE_TYPE_UNSUPPORTED` | 文件类型不支持 | 文件不属于允许的图片或 PDF 类型 |
| 13003 | 413 | `FILE_TOO_LARGE` | 上传文件超过大小限制 | 超过 Spring multipart 或业务配置上限 |
| 13004 | 404 | `FILE_NOT_FOUND` | 文件不存在 | 获取地址或删除时文件不存在/已删除 |
| 13005 | 503 | `STORAGE_UNAVAILABLE` | 文件存储服务不可用 | OSS 未配置、上传失败或签名地址生成失败 |

### 2.6 服务端错误

| 错误码 | HTTP | 标识 | 默认说明 | 常见场景 |
| --- | ---: | --- | --- | --- |
| 20001 | 500 | `INTERNAL_ERROR` | 服务器内部错误 | 未归类的服务端异常 |
| 20002 | 500 | `DATABASE_ERROR` | 数据库操作失败 | 数据源、SQL 或事务异常；唯一键冲突会优先映射为 10006 |

## 3. 异常映射顺序

后端按以下优先级映射异常：

1. 业务 `BaseException`：使用异常携带的规范错误码。
2. Bean Validation：`10007`。
3. JSON 解析错误：`10009`。
4. 缺少参数或 multipart part：`10012`。
5. 路径或查询参数类型不匹配：`10013`。
6. HTTP 方法/媒体类型错误：`10010`、`10011`。
7. 上传总大小超限：`13003`。
8. 静态路由不存在：`10005`。
9. 数据库唯一键冲突：`10006`。
10. 其他数据库错误：`20002`，只记录服务端日志。
11. 其他未知异常：`20001`，只记录服务端日志。

## 4. 客户端处理建议

| 错误码范围 | 建议处理 |
| --- | --- |
| 10001～10003、11001～11002 | 清理失效会话；登录失败时保留在登录页 |
| 10004 | 显示无权限提示，不自动重试 |
| 10005、12001～12003、13004 | 提示资源不存在并刷新当前列表 |
| 10006、11005、12005 | 提示冲突原因，保留用户当前编辑内容 |
| 10007、10009、10012～10013、12004 | 优先显示 `error` 字段并定位表单 |
| 10008 | 等待后重试，不进行并发立即重试 |
| 13001～13003 | 让用户重新选择符合要求的文件 |
| 13005、20001～20002 | 显示稍后重试，并记录 `request_id` 供排查 |

## 5. 新增错误码流程

1. 在 `ErrorCode` 中选择正确业务域，添加全局唯一编号、HTTP 状态和稳定中文说明。
2. 在业务异常中引用枚举，必要的动态信息放入 `detail`，不要拼入稳定 `message`。
3. 在本文档对应表格增加错误码。
4. 为错误码唯一性、HTTP 状态或异常映射增加测试。
5. 检查 `/v3/api-docs` 和 Swagger UI 中的统一错误响应模型。
